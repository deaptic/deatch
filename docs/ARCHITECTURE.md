# Architecture

Tauri 2, Windows only. Rust owns every connection to the outside world. The UI
is feature folders built from a pure model, one store, and pure views on a
shared kit.

## Frontend

```
src/
  app/         boot, shell, navigation, error boundaries
  platform/    the only code that imports @tauri-apps
  kit/         design system, toasts, clipboard; imports only kit and shared
  shared/      pure helpers used everywhere: i18n, format, keyboard, time
  features/    one folder per feature
  locales/
```

A feature:

```
features/activity/
  index.ts           the only import path into the feature
  model.ts           types and pure logic, apply(state, event)
  model.test.ts
  store.ts           state keyed by channel id, actions
  ActivityStrip.tsx  container: reads the store, passes data down
  ui/                pure views: data and callbacks in
```

Rules:

1. Imports flow `app → features → shared, kit, platform`. Features import each
   other only through `index.ts`.
2. Views in `ui/` never read stores. Only the container does.
3. State changes only through store actions. An event handler maps the raw
   payload with a pure, tested function (`model.ts`, `feed/entries/`) and
   calls one store action; it keeps only routing and permission checks.
4. Only `platform/` touches Tauri. The UI never fetches.
5. Each event kind has one owning feature, which listens in its `events.ts`.
   App events are typed in Rust. EventSub payloads pass through as JSON and are
   typed once on the TS side.
6. Per-channel state starts and ends through `channels.onChannel({ join,
   focus, leave })`, registered in the feature's own `start()`, never on mount.
   `app/createServices.ts` calls each feature's `start()` once.
7. kit owns visuals. Features use layout utilities only; text, colour,
   borders, and backgrounds come from kit components (`Text`, `Surface`, ...).
8. Permissions are asked one way: `hasPermission(channelId, capability)`.
9. Every screen region sits in an error boundary.
10. Pure modules import `shared/`, never a feature index: an index also loads
    that feature's UI.

Four tests guard the layout:

- `features/boundaries.test.ts` fails when a feature imports another feature
  past its `index.ts`.
- `features/purity.test.ts` fails when a file in `ui/` reads state, directly or
  through another file.
- `features/styling.test.ts` counts hand-written visual classes per view and
  fails when a file gains any; when a file loses some, lower its number.
- `app/modules.test.ts` loads every feature index as the first module, so an
  import cycle that reads a value too early fails there instead of at startup.

## Backend

```
src-tauri/src/
  main.rs lib.rs   wiring only
  platform/        error, http, ws, db, keyring, clock, emit, lock, local dir
  twitch/
    mod.rs         the Twitch client handle
    client/        Helix plumbing: transport, endpoints, pagination, params, ids
    auth/          sign-in, session, scopes
    eventsub/      subscriptions and the socket runner
    ads/ bits/ blocks/ channels/ charity/ chat/ chatters/ clips/ goals/
    hype_train/ moderation/ polls/ predictions/ raids/ search/ streams/
    subscriptions/ users/ whispers/
  emotes/ history/ feedlog/ link/ discord/ notifications/ diagnostics/ graphics/
```

A feature: `mod.rs` (the service), `dto.rs` (its types, exported to TS;
upstream types stop here), `events.rs` (events it emits), `commands.rs` (thin
commands taking one `params` struct, returning `Result<T>`).

`bindings.ts` is generated by `vp run bindings` and is the whole contract. A
test fails when it is stale. Helix requests retry and rate-limit in the
transport, never at call sites. The frontend only says which channels it wants;
the EventSub runner picks subscriptions and reconnects.

## Processes

By default `main.rs` runs the GUI. When a browser launches the exe for the Link
extension it runs as a native-messaging host instead and only relays frames to
the GUI pipe. `--export-bindings` writes the bindings and exits.

## Where things live

| What                       | Where                                              |
| -------------------------- | -------------------------------------------------- |
| Tokens                     | Windows credential store, `deatch` / `auth`        |
| Preferences, inbox, caches | WebView `localStorage`, keys in one constants file |
| Feed log, per account      | `%LOCALAPPDATA%\Deatch\data\<account id>.sqlite`   |
| App logs                   | `%LOCALAPPDATA%\com.deaptic.deatch\logs`           |
| Host logs                  | `%TEMP%\deatch-host.log`                           |
| Host manifests             | `%LOCALAPPDATA%\Deatch\` and their `HKCU` keys     |
